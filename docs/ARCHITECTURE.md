# MTGO CN Overlay 架构设计文档

## 一、项目愿景与安全准则

**MTGO CN Overlay** 是专为 **Magic: The Gathering Online (MTGO)** 桌面客户端打造的高性能实时中文悬浮翻译工具。

### 零封号安全承诺（Zero-Ban Risk Guarantee）
* **不读取、不写入 MTGO 进程内存**（无 ClrMD、无 ReadProcessMemory）。
* **不注入任何 DLL**（无 Hook、无 Detours）。
* **不发送模拟按键/鼠标操作**（无自动化脚本、无 Bot 功能）。
* **运行机制**：完全等同于 Snipaste、OBS 录屏工具或 Windows 放大镜——仅在屏幕视觉层进行局部截屏与本地 OCR 识别，完全符合 Daybreak / 威世智（WotC）的服务条款（ToS）。

## 三、核心技术实现细节

### 1. 为什么 Card Preview 停靠窗是 MTGO 的最佳切入点？
在 MTGO 中，战场上的卡牌可能会：
* 处于横置状态（90° 旋转，OCR 极易失败）；
* 微缩、堆叠或被指示物遮挡；
* 在手牌中受到视角梯形透视变形。

然而，**MTGO 的 Card Preview 窗格**（无论停靠在主界面哪一侧）具有以下特性：
1. 玩家只要光标掠过任何卡牌，该窗格都会立即更新为当前卡牌的**超大清晰竖向正视图**；
2. 卡名永远位于卡图顶部固定的相对比例坐标区（顶部 ~3% 到 10% 区域）；
3. 字体规范统一（Beleren 艺术字），背景对比度极高；
4. **性能极其省电**：仅当 Preview 窗格的像素哈希发生变化时才调用 OCR，平均每秒 0 次冗余计算。

### 2. OCR 与模糊纠错设计
* **引擎**：Windows 10/11 内置 `Windows.Media.Ocr.OcrEngine`，支持硬件加速，单次小图识别耗时约 5~15ms，体积 0 MB 额外依赖。
* **抗噪字典匹配**：
  * 将 OCR 文本进行字符规整：小写化、滤除非字母字符、易混淆字符映射（如 `0` $\to$ `o`, `1` $\to$ `l/i`, `5` $\to$ `s`）。
  * 匹配算法采用基于长度差剪枝的 Levenshtein 算法或 BK-Tree：
    * 字典容量：37,082 项；
    * 精确匹配：$O(1)$，耗时 < 0.2ms；
    * 模糊匹配（最大允许编辑距离 2~3）：耗时 < 2ms。

### 3. 悬浮窗体（Overlay）抗干扰机制
* 必须设置 Win32 扩展样式 `WS_EX_NOACTIVATE (0x08000000)`：
  保证浮窗在呼出、更新或重新渲染时，**绝不从 MTGO 抢走输入焦点**，玩家连续按 `F2`（让过优先权）、`F4`、`F6` 不会受到丝毫干扰。
* 样式 `WS_EX_TRANSPARENT (0x00000020)`：
  鼠标点击完全穿透，浮窗可直接覆盖在游戏界面上方而不阻碍操作。

## 四、项目技术栈

* **主机端运行时**：C# / .NET 8 (WindowsDesktop WPF)
* **Webview 容器**：Microsoft.Web.WebView2
* **OCR API**：Windows Runtime (`Windows.Media.Ocr`)
* **前端展示**：HTML5 + CSS3 (CSS Variables) + Vanilla JS + Mana Font (SVG/Font)
* **数据格式**：Gzip 压缩 JSON 字典（`en2zhs.json.gz`）
